# 风格3.0

用于产品外观设计的个人 Skill。根据产品参考图，在保留可见功能架构的前提下重构外观；可结合第二张风格参考图，迁移造型语言、材质和配色。

当前版本：**3.0.0**。此仓库保存技能源文件、参考规范、使用模板及改进反馈，便于跨设备维护和版本回退。

## 能做什么

- 根据产品图识别需要保留的功能件、位置和连接关系。
- 分层设计轮廓、体块、曲面、分件及细节。
- 从可选风格图中提取特征并应用到产品。
- 生成主视图，或基于已确认主视图扩展多视角。
- 按要求仅输出可复用的生图提示词。

技能本身是指令和参考文件，不包含独立图像生成服务。实际出图需要使用环境提供图像生成工具；没有该工具时按技能规则交付提示词。

## 使用方式

在支持本地 Skill 的客户端中，将 `skills/style-3-0/` 整个目录安装到该客户端的技能目录。不要只复制 `SKILL.md`，它引用的 `references/` 文件也需要保留。

本仓库同时保留插件清单，供支持相应格式的客户端导入。上传到 GitHub 本身不会自动安装技能，也不会自动将它保存为 ChatGPT 账号云端插件。

加载技能后，提供产品参考图 A；如需风格迁移，再提供风格参考图 B。使用示例：

```text
使用 $style-3-0。图 A 是产品参考，图 B 是风格参考。
保留图 A 的可见功能件数量、位置关系和操作方式，
提取图 B 的形体与材质语言，明显重构外壳，先生成一张主视图。
不要添加作者水印、署名或联系信息，不附加固定推广或免责声明。
```

其他示例：

- “使用风格3.0，只输出提示词，暂时不生成图片。”
- “主视图方向已确认，请基于这张图扩展正面、侧面和细节视图。”
- “只调整配色和材质，保持原有形体与功能布局。”

更完整的输入模板见 [设计请求模板](templates/design-request.md)。

## 上传到 GitHub

1. 创建自己的私有仓库，仓库名可使用 `style-3`。
2. 上传本文件所在目录中的内容，让 `README.md` 直接位于仓库根目录。
3. 保留子目录结构，以及 `.codex-plugin` 和 `.gitignore` 等以点开头的文件。
4. 提交后确认网页能显示 README，且 `skills/style-3-0/SKILL.md` 和参考文件齐全。

配套 ZIP 用于下载、备份或解压。仅把 ZIP 上传到仓库不会让 GitHub 自动展开里面的技能文件。若使用网页上传，需自行核对隐藏文件是否上传成功；使用 Git 客户端提交可保留完整结构。

## 优化和跨设备同步

以这个仓库作为统一维护源，不直接修改客户端的插件缓存作为长期维护方式。

1. 修改前先获取仓库最新版本。
2. 修改 `SKILL.md` 或参考规范，并记录改进原因。
3. 用相同产品参考图和请求对比修改前后的结果。
4. 在 [CHANGELOG.md](CHANGELOG.md) 记录变化，并提交到 GitHub。
5. 其他设备拉取更新，再更新其实际安装的技能副本并按客户端要求重新加载。

如果技能安装时是复制文件，更新仓库不会自动更新那份副本，需要重新复制或配置同步流程。多台设备修改同一文件时，应先合并修改再提交。

发布新版本时，同步修改以下位置的版本号：

- `plugin.json` 的 `version`。
- `.codex-plugin/plugin.json` 的 `version`。
- `skills/style-3-0/SKILL.md` 的 `metadata.version`。
- 本 README 的当前版本及 `CHANGELOG.md`。

保持技能内部名称 `style-3-0` 稳定，避免已有调用失效。Git 保存已提交的修改历史，便于对比和恢复；未提交的修改不会自动上传。

## 记录反馈

复制 [反馈模板](feedback/TEMPLATE.md)，保存为 `feedback/日期-问题简述.md`；也可以使用仓库的 Issues。

记录技能版本、输入、预期结果、实际问题、修改建议和复测结论。使用过程中的聊天、反馈、图片和记忆不会自动写入仓库，需要主动整理保存。

大型设计图片可放在另一个存储位置，在反馈中记录对应文件名或可访问链接。不要把密码、访问令牌或不打算分享的客户资料提交到仓库。
